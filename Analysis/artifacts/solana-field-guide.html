01 · Network & consensus

How the chain itself works

Solana is one global state machine run by validators. Its speed comes from a stack of techniques that each remove a bottleneck.

Proof of History Standard

A cryptographic clock: a chain of hashes that proves time passed between events, so validators agree on order without talking first.

Tower BFT Standard

Today's consensus. Validators vote on blocks using the PoH clock; full finality takes about 12.8 seconds.

Alpenglow (Votor) Coming

Replacement consensus targeting about 100–150 ms finality. Fast path at 80%+ first-round approval, slow path at 60–80%. Approved as SIMD-0326 in Sep 2025, on an Anza test cluster since May 2026, expected in Agave 4.3 (Oct 2026).

Rotor (Turbine replacement) deferred to a later proposal

Turbine Standard

Block propagation: the leader splits a block into small "shreds" and fans them out through a tree of validators, like BitTorrent.

Gulf Stream Standard

No public mempool. Transactions are forwarded straight to upcoming leaders, who are known in advance from the leader schedule.

Sealevel Standard

Parallel execution. Each transaction declares which accounts it reads and writes, so non-overlapping transactions run at the same time on many cores.

Slots, leaders, epochs Standard

Time is cut into slots; one validator leads each slot. The leader schedule is fixed per epoch (about two days) by stake weight.

Stake-weighted QoS Standard

Leaders reserve inbound connection capacity for traffic from staked validators, so spam can't crowd out real transactions.

Validator clients Live

Agave (Anza), Firedancer / Frankendancer (Jump), and Jito-Solana (Agave fork with MEV support). Multiple clients reduce the risk of one bug halting the network.

XDP networking Live

Kernel-bypass networking for validators, cutting packet latency about 200×. In Agave 4.0+ and on by default in Firedancer.

03 · Accounts & state

Everything is an account

Code and data are both stored in accounts. Programs are stateless; they read and write accounts passed into each instruction.

Account structure Standard

Each account has an address, a balance in lamports (1 SOL = 1 billion lamports), a data byte array, an owner program, and an executable flag.

Ownership rules Standard

Only the owner program may change an account's data or debit its lamports. Anyone may credit lamports. This is the core security model.

Rent & rent exemption Standard

Accounts must hold a minimum balance proportional to their size to stay alive. The deposit is returned when the account is closed. A 90% rent cut is partly activated.

Program Derived Addresses Standard

Deterministic addresses derived from seeds and a program ID, with no private key. Only that program can sign for them, which makes PDAs the standard way to hold program-owned state and escrow.

Account types Standard

Wallet (system-owned) accounts, program accounts (executable), program data accounts, token accounts, sysvars (clock, rent, slot hashes, instructions).

Address Lookup Tables Standard

On-chain tables of addresses that v0 transactions reference by 1-byte index, so one transaction can touch many more accounts.

State compression Standard

Store only a Merkle root on chain and the leaves in the ledger. Powers compressed NFTs at a tiny fraction of normal cost.

ZK Compression (Light Protocol) Live

Rent-free compressed accounts and tokens, kept valid with small zero-knowledge proofs. V2 batched Merkle trees went live Jan 2026 (~250× cheaper per update, ~70% less CU). The Light Token Program is on devnet, mainnet planned.

04 · Transactions & fees

How you change state, and what it costs

A transaction is a list of instructions plus signatures and a recent blockhash. It succeeds or fails atomically.

Instructions Standard

Each names a program, the accounts it touches (read-only or writable, signer or not), and input bytes. Programs can inspect other instructions in the same transaction (introspection).

Versioned transactions (v0) Standard

Adds Address Lookup Table support. Legacy transactions still work.

Transaction size Live

Up to 4,096 bytes since Agave 4.2 (was 1,232).

Durable nonces Standard

Replace the expiring blockhash with a stored nonce, so a transaction can be signed now and sent much later. Used for offline and multi-party signing.

Partial signing Standard

Several parties sign the same transaction separately, for example a user plus a fee payer.

Base fee Standard

5,000 lamports per signature. 50% burned, 50% to the validator. Charged even if the transaction fails.

Priority fees Standard

Optional tip per compute unit: ceil(CU price × CU limit ÷ 1,000,000) lamports. 100% goes to the validator.

Compute budget Standard

Default 200,000 CU per non-builtin instruction and 3,000 per builtin. Set a limit and price with the Compute Budget program. Blocks hold 100M CU.

Fee abstraction (Kora) Live

A paymaster JSON-RPC server that pays SOL fees and lets users pay in SPL tokens such as USDC. Integrates with the Kit client.

Confirmation levels Standard

processed → confirmed (supermajority voted) → finalized (rooted). Alpenglow will collapse this to about 150 ms.

MEV protection Live

Docs cover protecting users from sandwiching via private routing and bundle services; see Staking & MEV.

05 · Programs & runtime

Smart contracts on Solana

Programs are compiled to sBPF bytecode and run in the Solana Virtual Machine (SVM). They are upgradeable by default unless the upgrade authority is removed.

System Program Core

Creates accounts, allocates space, assigns owners, transfers SOL.

Vote & Stake programs Core

Validator voting, and delegating SOL to validators through stake accounts.

Compute Budget program Core

Sets compute limits and priority fees per transaction.

Address Lookup Table program Core

Creates and extends lookup tables.

BPF loaders Core

Deploy, upgrade and close programs (upgradeable loader v3, loader v4).

ZK ElGamal Proof program Core

Verifies zero-knowledge proofs used by confidential token balances.

Precompiles Core

Signature checks for Ed25519, Secp256k1 (Ethereum-style keys) and Secp256r1 (passkeys and phone secure enclaves).

New crypto syscalls Live

BN254 G2 and BLS12-381 operations, for ZK verifiers and aggregate signatures.

Cross-Program Invocation Standard

Programs call other programs, passing accounts and privileges along. A program signs for its own PDAs with invoke_signed. Nesting depth is capped.

Frameworks Standard

Anchor (most common, IDL + safety macros), Pinocchio (zero-dependency, high performance), native Rust.

IDL & client generation Standard

Programs publish an interface (IDL) from which typed clients are generated (Codama).

Verified builds Standard

Reproducible builds prove deployed bytecode matches public source code.

sBPFv3 Coming

Required target for new deployments from Agave 4.4 (Nov 2026).

06 · Tokens

Two token programs and twenty-seven extensions

Every fungible token and most NFTs use one of two programs. A mint defines the token; token accounts hold balances.

SPL Token (now P-Token) Live

Create mint, create account, mint, transfer, burn, approve / revoke delegate, freeze / thaw, set authority, close account, sync native (wrapped SOL). Now runs as the optimized P-Token implementation.

One delegate per token account at a time

Token-2022 (Token Extensions) Standard

A second token program with optional extensions chosen when the mint or account is created. Listed in full below.

Token ACL Standard

Permissioned tokens: allow or block lists for who may hold or move a token, aimed at regulated assets.

Metaplex metadata Standard

Name, symbol, image and attributes for SPL tokens and NFTs.

Token verification Standard

Guidance for proving a token is the real one, not a lookalike.

07 · NFTs & digital ownership

Collectibles, memberships, tickets

Metaplex Token Metadata Standard

The original NFT standard: an SPL token with supply 1 plus a metadata account.

Metaplex Core Standard

Single-account NFTs with plugins (royalties, freeze, attributes). Cheaper and simpler than Token Metadata.

Compressed NFTs (Bubblegum v2) Live

Millions of NFTs for a few SOL using state compression. V2 adds Core collections, freeze / thaw and soulbound cNFTs.

Token-2022 NFTs Standard

NFTs with built-in metadata, groups and dynamic metadata that changes over time.

08 · Payments & commerce

Moving money

The docs now have a full payments section: accept, send, batch, subscriptions and fee abstraction.

Basic payments Standard

SOL or token transfers with memos, address verification and confirmation tracking.

Batch payments Standard

Many transfers in one transaction, e.g. payroll. Larger 4,096-byte transactions fit more.

Subscriptions Standard

Recurring payments via token delegation and scheduled pulls; covered in the docs' subscriptions overview.

Solana Pay Standard

URL and QR standard for wallet payments, online and at point of sale.

Actions & Blinks Standard

Any transaction (pay, vote, mint, swap, stake) packaged as a shareable link that unfurls into a button on X, websites or chat. Built by Dialect and the Solana Foundation.

Commerce Kit Live

Drop-in payment components and checkout flows for apps.

x402 facilitator Live

HTTP 402 pay-per-request payments for APIs and AI agents. @x402/svm package; facilitators PayAI and Coinbase CDP. "Exact" pricing live; "upto" announced by Coinbase on 17 Sep 2026 but the x402 FAQ still lists it as EVM-only.

Delivery vs Payment Standard

Asset and cash swap atomically in one transaction, so neither side can default.

NAV strikes Standard

Docs pattern for money-market funds publishing net asset value on chain.

09 · Identity, privacy, security

Who you are, what stays hidden, what keeps keys safe

Solana Attestation Service Live

Open protocol for verifiable credentials tied to a wallet: KYC "passports", region checks, accredited-investor status. Reusable across apps without putting personal data on chain. Civic issues on it.

Solana Name Service (.sol) Standard

Human-readable names that resolve to wallets.

Confidential balances Standard

Token-2022 extensions that hide amounts with ElGamal encryption and ZK proofs, with optional auditor keys for compliance.

Private Channels Live

Listed in the docs' tools section as a privacy product with integration resources.

Arcium Live

Encrypted computation network (multi-party computation). Mainnet Alpha on Solana; Umbra runs shielded transfers and swaps on it. Over 1 million confidential computations by mid-2026.

Private Ephemeral Rollups Live

MagicBlock's confidential execution inside Intel TDX enclaves, still composable with Solana.

Keychain Live

One signing interface over local keys, cloud KMS, HSMs and wallets.

Passkeys (Secp256r1) Standard

Precompile lets phones' secure enclaves and passkeys sign Solana transactions.

Multisig & smart accounts Standard

Squads: shared treasuries, approvals, spending limits with allowed destinations and periods.

10 · Scaling layers

Going faster than the base chain

Ephemeral Rollups (MagicBlock) Live

Delegate accounts into a temporary fast SVM instance (about 10 ms latency), then commit results back to Solana. Used for games and real-time apps; over a billion transactions on its MagicNet canary.

ZK Compression Live

Scales state, not speed: millions of accounts without rent. See Accounts.

Bigger, faster blocks Live

100M CU blocks, P-Token efficiency, 4 KB transactions, with 200 ms slots partly active.

11 · Data, oracles, bridges

Reading the chain and connecting it to the world

RPC HTTP API Standard

Methods for accounts, blocks, epochs, fees, leaders, supply, tokens, transactions and signatures, e.g. getAccountInfo, getTransaction, simulateTransaction, getTokenAccountsByOwner.

RPC WebSocket Standard

Live subscriptions to accounts, programs, logs, signatures, slots, blocks, roots and votes.

RPC providers & streaming Standard

Helius, Triton, QuickNode, Chainstack, Alchemy and others; Geyser plugins stream account updates directly from validators.

Pyth & Pyth Lazer Live

The default price oracle on Solana, with confidence intervals. Lazer serves sub-millisecond feeds for trading apps.

RedStone Live

Oracle named as a migration target for former Switchboard users.

Switchboard Gone

Shut down 25 Sep 2026 with six days' notice. Kamino, Jito, MarginFi and Drift had to migrate to Pyth or RedStone.

Wormhole Live

Cross-chain messaging and token transfers; most complete developer messaging stack. About 1–3 minutes for typical USDC or SOL corridors.

deBridge (DLN) Live

Liquidity bridge with no pooled funds: market makers fill orders natively and instantly.

LayerZero Live

Omnichain messaging between Solana and 70+ chains.

14 · Staking & MEV

Securing the network and ordering transactions

Native staking Standard

Delegate SOL to validators through stake accounts; rewards each epoch from inflation and fees.

Liquid staking Live

Stake and receive a tradeable token: Jito (JitoSOL), Marinade (mSOL), Sanctum (many LSTs and instant unstake).

Jito bundles & tips Live

Send groups of transactions that land together or not at all, with a tip to the validator.

Jito BAM Live

Block Assembly Marketplace: open-source block building with private ordering and app-controlled execution plugins. About 33–34% of stake in 2026, with preconfirmations live.

Where users hold keys

Seeker phone Live

Solana Mobile's second phone (shipping since Aug 2025, about $500) with a hardware Seed Vault isolating private keys.

SKR token Live

Launched Jan 2026; rewards users, builders, hardware makers and Guardian node operators in the mobile ecosystem.

Mobile Wallet Adapter Standard

Lets any Android app ask an installed wallet to sign. Part of the Solana Mobile Stack with the dApp Store.

Browser & app wallets Standard

Phantom, Solflare, Backpack and others, connected through Wallet Standard.

Embedded wallets Standard
